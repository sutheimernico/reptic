| Path | Time | Verdict |
|---|---|---|
| Migration on an up-to-date DB (every cold start) | ~0 ms | fine |

| Same, one calendar month | 71 ms | same cause |

| Auto-backup export + serialize (once a day, after first render) | 134 ms, 5 MB | acceptable; report only |
| Rest-timer tick | re-renders only `RestTimerBanner` (local `now` state; provider value changes on start/dismiss only) | fine — no memo work needed; React Compiler is on |

## Tasks

### Task 1 — Progression suggestion (double progression)
**Files:** new `src/domain/progression.ts` + test; `src/app/session/exercise.tsx`;
`src/app/(tabs)/settings.tsx`; `src/__tests__/session-exercise.test.tsx`.
- Rule over last time's sets (same source as the "letztes Mal" line): working sets =
  performed sets (reps ≥ 1, weight > 0) at the top weight. All of them at or above the
  rep target → "Vorschlag: +increment kg"; otherwise "bei X kg bleiben, Ziel N Wdh.".
- Plate stock respected: when last time's weight is exactly loadable on the bar, the
  suggestion rounds up to the next loadable weight; machine/dumbbell weights (not
  loadable) get the plain increment.
- Quiet when: no prior performed sets, cardio, bodyweight (no weight), or the prior sets
  came from another gym (different machines).
- Display-only hint above the sets; an explicit "Übernehmen" tap moves the not-yet-done
  rows still at the old working weight to the suggestion. Never automatic.
- Settings: "Wdh.-Ziel" (default 12, 1-step stepper, 3–30) and "Steigerung"
  (default 2.5 kg; 1 / 1.25 / 2 / 2.5 / 5).

**Accept:** rule fully unit-tested (quiet cases, warm-up ignored, plate rounding, machine
weights, settings parsing); component test shows the hint and the Übernehmen write.

### Perf findings (node:sqlite, 624 sessions / 17,472 sets; a phone is slower)

- **Fixed:** the Verlauf list (see above). The cost grew with sessions × sets, so with
  Nico's two months of data it is barely noticeable yet. It would have hit around year one.
- **Measured, left alone:** migration on an up-to-date DB ~0 ms; set-screen queries
  0.6–1.4 ms; trends 4.6 ms; the rest-timer tick only re-renders its own banner
  (React Compiler is on, so no hand-written memo is needed). The daily auto-backup takes
  134 ms for 5 MB at three years, after the first render. The file is pretty-printed JSON,
  so dropping the indentation would roughly halve it. That is optional and was not done,
  because the backup format is Nico's safety net and should not change in passing.

### Deviations (and why)

1. **App icon + splash dropped.** They were already real. Phase 12 (`9b0739d`) shipped
   Nico's own pick from the icon review ("design D", barbell, indigo→violet) for every
   Android asset. The Needs-Nico line and the README still said "Expo template" and were
   out of date. Both are corrected. Generating a new mark would have overridden his
   decision.
2. **Rep target is global, not per exercise.** No rep-target concept existed. A
   per-exercise one needs either a schema change or hidden per-exercise settings rows that
   backups do not carry. One global 12 fits his machine/cable library. If single
   exercises need a different target, that is the follow-up (feel-veto below).
3. **One hint row per exercise, not on every "letztes Mal" line.** The decision is made
   per exercise, so repeating it on 3–4 rows would only add noise.
4. **"Übernehmen" added.** The hint itself never writes anything. Typing 62.5 into four
   fields between sets is exactly the friction the hint is meant to remove.
5. **Perf fix by query rewrite, not an index.** An index would have meant a v4 migration
   on real device data. The rewrite is faster than the brief needed and needs no migration.
6. **Small additions inside the touched flows:** finishing a session dismisses the rest
   timer, so it cannot buzz after the session ends. The PR measure SQL is shared between
   the live badge and the summary, so they cannot disagree (no behaviour change,
   existing tests pinned). The clock is also shown on the set screen, where most of the
   gym time is spent.

### Nico's smoke test v1.2 (on device, together with the v1.1 list in `2026-07-21-daily-gym-companion.md`)

1. **Progression hint.** Open an exercise whose last session in *this* gym had every set
   at 12+ reps. You should see "Vorschlag: … kg" and "Übernehmen". Tap it: only sets you
   have not ticked and that still show the old weight change. Then open one with a
   short set: you should see "bei … kg bleiben". Check that a barbell weight rounds to
   your plates, and that the same exercise shows no hint in another gym.
2. **Settings.** Einstellungen → Training → "Wdh.-Ziel für Steigerung" and "Steigerung".
   Change them and reopen an exercise: the hint follows.
3. **Summary.** Finish a session. Do the numbers match the Verlauf row? Is the comparison
   the last session with the *same* plans? Are the records sensible? "Fertig" **and the
   Android back gesture** must both land on Heute, never on the closed session.
4. **Summary from history.** Verlauf → a session → "Zusammenfassung" opens the same
   screen without the Fertig button, and an old session keeps its records.
5. **Clock.** It ticks in both headers. Lock the phone for two minutes: it must show two
   minutes more, not the old time. Long exercise names must stay readable next to it.
6. **Verlauf.** It opens instantly, and the set counts and volume per session are the same
   as before the update.
